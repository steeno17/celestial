// notes for me:
the webassembly module object has one big block of memory ( linear memory ), which is implemented
as an array buffer

javascrip can't directly access memory, so emscripten creates typed arrays in 
sizes of: HEAPU8, HEAP32, HEAPF32, HEAPF64 ( f denoting floating point, u = unsigned int),
over the actual underlying heap buffer ( kind of like a handle access to it )

typed array points are indexed by the elements, but pointers are a byte offset of some X ( x : element size in bytes )

a double in C++ is 8 bytes, so somePointer / 8 would give the index to access, hence why I used raPtr / elementsPerNumber


I vendored the globegl library instead of fetching it online, to keep everything local and not worry about dependancies
-- so instead of fetching it with a script tag, i just directly load the library from /vendor (../vendor/globe.gl/globe.gl.min.js)
